## 1. 完成范围

本任务在保留 `empty-v1`、`small-v1`、嵌套引用 remap 和 canonical business hash 行为的基础上，补齐以下三类确定性夹具：

- `large-synthetic-v1`：最大正常合成项目，覆盖编辑器、图谱和长篇记忆负载形态；
- `blob-ladder-v1`：10 MiB、100 MiB、500 MiB、1 GiB 的流式二进制配方与固定 SHA-256；
- `legacy-matrix-v1`：从当前真实 Dexie schema 版本声明派生的 v1～v37 升级矩阵。

所有业务表覆盖、导入导出表集合和引用验证均从 `PROJECT_TABLES` 派生，没有维护第二份业务表清单。未修改 `CONTEXT_SOURCES`、`FIELD_REGISTRY`、`PROJECT_TABLES` 的约束或业务语义。

## 5. Legacy Matrix

legacy matrix 直接读取当前 `StoryForgeDB` 的真实 Dexie 版本声明，不维护手抄 schema：

1. 从 `_versions` 派生连续版本 v1～v37 及各版本真实 `storesSource`；
2. 为每个版本建立隔离的最小旧库；
3. 只写入从 v1 起真实存在的项目字段，不虚构历史字段；
4. 使用真实 `StoryForgeDB` 升级到 v37；
5. 从 `PROJECT_TABLES` 派生当前表集合并计算最新规范化状态 hash；
6. 37 个源版本必须得到同一个最新状态 hash：
   `75125e0950c5e1bfe7b3ee634585e0dd8c485e50b92666490a96e8f4ec571e57`。

产物是可重建配方和断言，不是浏览器 profile、LevelDB 快照或真实用户数据库。

## 6. 确定性与损坏检测

采用 property-based-testing 技能中的确定性、往返、不变量和负例设计原则，覆盖：

- 同一 seed/坐标生成相同 ID、正文和 Blob 分块；不同坐标产生不同结果；
- committed artifact 与重新生成结果逐字节相同；
- project import/export 后主键全部更新，但业务 canonical hash 不变；
- `PROJECT_TABLES.refs` 和 `exportRemap` 声明的引用全部完整；
- canonicalizer 对业务字段、数组顺序和嵌套数据变化敏感；
- Blob 单字节损坏会改变 SHA-256；
- manifest 拒绝文件篡改、BOM、CRLF、非 canonical JSON、路径穿越、未知字段和非 PASS 断言；
- legacy 任一版本升级结果偏离统一最新 hash 时失败关闭。

## 8. 未完成项与资源风险

- `real-anonymized-v1` 仍为可选 `NOT_AVAILABLE`；本任务没有读取真实浏览器数据；
- D0.4 的生产 `web-tab` 动态功能、性能、恢复和安全采集仍未完成，因此总体仍为 `NOT_ELIGIBLE`；
- 默认物化 Blob 阶梯需要 639,631,360 B（约 610 MiB）磁盘；包含 1 GiB 时合计需要 1,713,373,184 B（约 1.60 GiB）；
- Blob 数据缓冲固定为 1 MiB，但哈希库和 Node 运行时仍有少量额外内存开销；
- large 生成和往返会同时持有多份约 9.3 MB JSON 数据图，实际峰值内存未在本夹具任务中作为性能基线测量。
