## 2. D1.1 独立结论

### 2.1 已确认实现

- `src-tauri/` 是正式 Tauri 2 工程；`main.rs` 只转发到 `storyforge_desktop_lib::run()`。
- Rust 没有注册 command、IPC handler 或 plugin。
- `tauri = 2.11.5`、`tauri-build = 2.6.3`、`@tauri-apps/api = 2.11.0`、`@tauri-apps/cli = 2.11.2` 均精确固定版本。
- release 默认启用 `custom-protocol`，离线资源来自 `dist-desktop/`。
- capability 只绑定 `main` 窗口并开放 `core:default`。
- CSP 非空，包含 `object-src 'none'`、`base-uri 'self'`、`form-action 'self'`、`frame-ancestors 'none'` 等限制。
- Tauri RuntimeAdapter 对尚未实现的网络、文件、凭据、剪贴板、外链和持久化申请统一 typed fail-closed。
- dev/stable 的产品名、identifier、标题和数据身份分离；stable overlay 明确设置 `devtools: false`。
- 正常 stable 构建的 bundle/exe 包含 stable identifier，不含 dev identifier、`remote-debugging-port` 或 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS`。stable artifact 本身不会默认获得 CDP 参数。

### 2.2 Finding

#### [P2] pdf.js worker 只有产物存在检查，没有实际加载检查

`docs/WINDOWS-DESKTOP-IMPLEMENTATION-PLAN.md` D1.1 验证要求 React lazy chunks、CSS、字体和 pdf.js worker 均能加载。当前 `scripts/check-desktop-build-contract.mjs` 只检查 `assets/pdf.worker-*.mjs` 文件存在；`scripts/windows-desktop-route-smoke.mjs` 也没有创建 worker 或等待其 ready/error。

因此，pdf.js worker 在 Tauri custom protocol、离线资源和当前 CSP 下能否实际启动，仍缺少独立运行证据。建议在仅允许 dev identity 的离线 smoke 中启动 worker，并同时验证成功消息与 error/timeout。

### 2.3 D1.1 结论

D1.1 已具备继续审查的代码基础，但在补齐 pdf.js worker 实际加载证据、恢复仓库全量门禁并闭环 D0.2/D0.4/D0.5 前，不具备最终合并批准或任务 `PASS` 条件。

## 3. D1.2 独立结论

### 3.1 已确认实现

- Web 使用 `base=/storyforge/`、BrowserRouter、manifest、Service Worker、Workbox 和 `dist/`。
- Desktop 使用 `base=./`、HashRouter、独立 `dist-desktop/`，不生成 manifest、Service Worker 或 Workbox。
- 四个本地字体资产同时进入 Web/Desktop 产物，Web Service Worker 预缓存字体。
- Desktop 产物不存在 `/storyforge/` 绝对资源路径。
- Web/Desktop 构建差异主要由 `VITE_RUNTIME_TARGET` 控制。
- 动态端口、唯一 profile、运行记录、PID 树停止和端口关闭验证均已实现。

### 3.2 Findings

#### [P1] stable artifact 在启动前不会被拒绝

`scripts/windows-desktop-route-smoke.mjs` 的 `run()` 只检查平台、exe 是否存在及同路径进程，然后立即调用 `launchDesktop('initial')`。dev identifier 要等进程启动、CDP 连接、页面 bundle 读取及多次路由/数据交互后才通过 `runtime.devIdentityMarker` 断言。

如果误传 stable exe，脚本会先给它注入 CDP 参数、启动进程并执行合成数据交互，最后才拒绝。这违反 `APP-IDENTITY-DECISION.md` 中“stable profile 禁止 CDP/自动化”的边界。必须在 `spawn()` 之前验证 artifact 身份并 fail closed。

#### [P2] WebView2 调试参数不是完全受控的动态参数

smoke 会继承宿主进程已有的 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS`，再追加动态端口。如果环境中已有固定 `--remote-debugging-port` 或其他未记录参数，本次运行无法保证只使用受控动态端口。

建议只构造本次运行所需参数，或在启动前拒绝重复端口、固定端口及非允许开关。

#### [P2] Desktop dev 仍执行 Web localhost Cache/SW 清理逻辑

`index.html` 的本地自愈脚本只依据 `localhost`、`127.0.0.1` 或 IPv6 loopback 判断是否注销 Service Worker、清理 Cache Storage。Desktop dev URL 为 `127.0.0.1:1420`，因此 Desktop dev WebView 仍会执行该 Web 专属逻辑。

这与 D1.2 明确要求“Desktop 不执行 Web 本地开发环境的 Cache/SW 清理逻辑”不一致，也意味着该差异没有完全由单一 runtime target 控制。

### 3.3 D1.2 结论

D1.2 当前不具备合并批准条件。至少需要：

1. 在启动前拒绝 stable artifact；
2. 清除或严格校验继承的 WebView2 调试参数；
3. 使用 runtime target 隔离 localhost Cache/SW 清理；
4. 为上述边界增加可重复自动化测试；
5. 重新执行 dev-identity route smoke、双构建和 Web 回归验证。
