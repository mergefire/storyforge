## 怎么配合两份文档用

- **想知道"有哪些 AI 动作、读什么变量、写哪些字段"** → 看 `.generated.md`(代码扫描,永远准)
- **想知道"这个动作为什么这么设计、有什么坑"** → 看本文件
- **修改 AI 行为后** → `npm run gen:ai-manual` 重新生成 generated 版;必要时在此补语义注解

## 核心动作语义注解

### AI 配置、预设与模型发现
- **模型发现**：本地模型与自定义 OpenAI-compatible 服务通过运行时固定的 `/models` 操作刷新列表；按 provider + 规范化 base URL 缓存，接口失败时保留手动输入能力。
- **预设凭据**：每个预设使用独立的本机凭据槽；切换 A→B→A 或重启应用后会恢复对应 Key 到配置输入，不能把一个预设的 Key 误绑定给另一个 provider / endpoint。
- **桌面边界**：Windows 设备级 Key 保存在凭据管理器；只有 AI 配置界面的显式恢复命令可以按 AI 凭据键读取，Gist 等其它 secret 不允许走该回显路径。

### 章节正文生成 — `moduleKey: chapter.content`
- **产品设计**:正文编辑器的统一任务模型、范围规则与候选流程见 [`CHAPTER-AI-EDITOR-DESIGN.md`](./CHAPTER-AI-EDITOR-DESIGN.md)。
- **业务意图**:项目最核心的功能。读取最丰富的上下文(世界观/角色/状态/伏笔/词条/真实与幻想规则/上一章结尾),经三层记忆预算分配后生成正文。
- **多世界**:按章节所属世界(沿大纲父链解析)装配上下文,不串台。
- **章纲前置**:正文生成必须读取当前章节关联的章纲；关联缺失或章纲为空时停止生成并引导用户先补章纲。默认可一键生成，作者要求是可选的本轮补充条件。
- **真实任务模型**:每轮先用任务路由解析实际创作 provider/model、上下文窗口和输出上限，再用同一份配置装配和发送；设置页当前模型不再被误当成本轮实际模型，1M 窗口不会回退成 8K/2K 预算。
- **当前稿件**:装配器仍从注册表取 `chapterContent`，但请求开始时用编辑器当前纯文本覆盖该来源，因此作者尚未自动保存的改动也能进入上下文、来源统计和预算。
- **细纲规则**:细纲是可选增强。不存在或没有有效场景时仍按章纲生成；存在时保护并完整注入场景顺序、摘要、人物、地点、冲突、节奏、预计字数、备注、衔接、悬念、情绪与伏笔；损坏关联不会被当成依据。
- **预算解释**:UI 分开说明来源自身限额、总模型窗口裁剪和 AI 语义压缩，并显示准备读取、实际读取、真实模型、窗口、输入 token 与输出上限。
- **候选原则**:生成、重写和续写都先成为候选，不直接覆盖正文；空输出、Markdown/Prompt/分析说明、拒答、只读上下文回显或明显非正文会被阻断采纳，但仍可查看、复制、修改要求和重试。

### 章节对话协作 — `moduleKey: chapter.assistant`
- **业务意图**:把正文生成、续写、去 AI 味、框选定点修改和自由对话收口到同一候选工作流；AI 先给候选，用户继续追问或确认后才写回正文。
- **读写边界**:无选区时默认以整章为可写目标；有选区时仍读取整章、章纲和项目资料以保持人物与情节连续，但可写目标被锁定为选区，候选不得包含选区前后邻文。
- **任务状态**:正文任务显式区分生成中、完成、停止、失败、阻断、已采纳和已放弃；停止后的半成品不能正常采纳，失败/冲突/阻断不会清掉旧候选和指令。
- **并发与恢复**:同一章节同一时间只允许一个正文任务从准备阶段进入运行；重复入口会被同步拒绝，旧任务的延迟回调不能停止或覆盖新任务。流式正文会周期性写入本地恢复缓存，传输中断或应用意外关闭后以未完成输出恢复，并可从保留内容继续生成完整候选。
- **固定写回**:整章生成/重写只允许替换整章，续写只允许追加，选区任务只允许替换原选区，讨论没有采纳入口；不再提供可把整章误追加或把续写误覆盖整章的危险切换。
- **数据安全**:任务建立时保存章节正文 hash，续写再保存尾部锚点，选区再保存坐标、原文和邻文。采纳前先校验版本并创建项目快照，再经 `adopt()`；拒绝或异常会恢复编辑器 HTML/React state 并保留会话。成功后清空本次会话，在会话外提供受采纳后版本保护的撤销；作者已继续编辑时改为引导从快照恢复。
- **选区协作**:选区在讨论和生成期间用非持久化 Decoration 高亮，不进入 HTML/数据库/导出。讨论回复可直接转润色、扩写、缩写或重写并继续锁定原范围；超长或失效范围会明确提示且禁止采纳。
- **候选审阅**:选区候选在侧栏显示字词级 diff、字数变化和锁定范围；整章候选进入中央稿纸审阅，可切换原文/候选、行内/并排 diff、导航变更并识别大幅删改。候选全文只存在候选对象和审阅区，聊天只保留版本摘要。
- **长期事实**:“提取长期事实”先生成章节内可编辑候选；证据必须逐字存在于正文，作者确认后才经注册表写入并成为后续章节权威事实，整批放弃不会污染上下文。
- **会话与布局**:用户/AI/系统消息语义分离；仅用户靠近底部时自动跟随新 token；危险清空需确认。面板宽度、开关和按章节会话在本地持久化，宽/中/窄/极窄窗口使用同一业务实现。

### 灵感反推 — `moduleKey: inspiration.reverse`
- **业务意图**:用户写碎片想法,AI 反向生成世界观/故事核心/角色草稿。是"下游→上游"的反推流。
- **角色模型**:角色草稿必须同时产出戏份权重与九宫格阵营两轴；旧 `role` 只作为派生兼容字段。
- **坑**:写回经 `adopt()`,AI 输出的别名字段(如 `summary`→`worldOrigin`)自动归一,不再静默丢字段(Phase 1.2b 修复)。

### 角色生成 — `moduleKey: character.generate`
- **业务意图**:根据现有阵容与世界上下文设计角色；戏份(main/secondary/NPC/路人)与阵营(道德轴×秩序轴)彼此独立。
- **写回约束**:`roleWeight`、`moralAxis`、`orderAxis` 三项必填；`role` 由注册表写回层统一派生，调用方不得手写兼容映射。

### 状态提取 — `moduleKey:`(无独立模板,走 state-extract-adapter)
- **业务意图**:章节写完后自动从正文提取已登记角色的动态状态,写回角色状态卡。
- **坑**:用"按需召回"只把相关状态卡喂给 AI；角色名单同时作为严格白名单，地点、物品、文件夹、组织等不能再被误建为角色卡。

### 词条拆分 — `moduleKey: codex.extract`
- **业务意图**:把世界观各方面的整段“全貌”拆成当前分类下的结构化词条，用户确认后经 `adopt()` 批量写入。
- **长文本**:按段落/句子分块，保留重叠区，避免只读取开头；跨块按规范名去重。
- **标签**:默认可关闭；开启“AI 补充词条标签”会增加输出 token，标签作为检索元数据，不覆盖分类专属字段。

### 重要地点提取 — `moduleKey: location.extract`
- **业务意图**:从已写章节中筛出反复出现或推动剧情的重要地点，先给候选，确认后写入地点树的顶层。
- **边界**:普通方位词、一闪而过的房间/道路不应入库；标签只允许使用地点注册表里的合法标签。

### 物品栏提取 — `moduleKey: inventory.extract`
- **业务意图**:逐章提取主角/核心视角人物真实发生的获得与消耗，聚合当前持有量与流水。
- **数据安全**:整章全部分块成功后才替换该章旧流水；任一分块失败时保留原记录。

### 故事年表提取 — `moduleKey: story-timeline.extract`
- **业务意图**:从正文提取推动剧情的事件，并按章节进程展示；事件可直接跳转到来源章节。

### 工作流执行 — (WorkflowRunner)
- **业务意图**:多步 prompt 编排,上一步输出喂给下一步。
- **坑**:每步现在带用户当前输入 + 项目上下文(BUG-INPUT-WITH-GEN 相关,部分由 Phase 2.3 覆盖)。
